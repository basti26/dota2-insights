```powershell
python tools/plan_pi_migration.py --legacy-config <旧本机配置JSON>
```

当前14个文件约140KiB；保留library.py、pi_ward_worker.py、extract_replay_wards.py的既有服务入口，额外部署所需dota2_insights模块和data/validation-locks.json。只带本仓库源码及公共锁，不带Windows解析依赖、配置、凭据、DEM、截图、声音或个人记录。外部依赖根gem/google/snappy仅列为待核查，未声称已验证ARM环境。适用目标是现有非冻结Linux Python托管程序，不是给Pi部署Windows EXE。

源码闭包经临时目录隔离子进程验证：Python以-I -S启动，只加入生成清单目录，不使用Helper源码、父进程模块缓存或site-packages。可以导入入口及分析适配模块，公共锁仍拒收封存比赛；未加载Gem解析实体或处理真实录像。这个检查不证明Pi上的架构、Protobuf/Snappy二进制或服务权限通过。

同时修复了独立解析入口：公开锁名单在源码模式也必须存在；已知封存文件名在文件打开/游戏进程查询前拒收；伪装文件名须先取得有界footer比赛号并检查，再进行全文件SHA或实体解析。旧的外层工作队列门禁不再是唯一保障。

## 尚未执行的远端步骤

1. 用户明确授权部署后，先只读确认服务、正在处理的比赛和队列；有真实解析进程时等待其结束，不把旧worker_status文件当活进程，也不重启活跃任务。
2. 备份程序、用户服务定义和现存状态配置；保留可恢复版本。只改变程序及公共锁名单，不移动录像和分析报告，不清理任何原数据。
3. 在Pi核对固定Gem 0.13.0及既定提交、Protobuf便携实现、Snappy和可用内存/磁盘。实际依赖由Pi既有环境提供，不上传Windows.replay-deps。
4. 审核新清单及导入自检后，才更新程序并重启用户服务；失败则回退程序版本，失败录像保持未完成，不填成功状态。
5. 用单场非封存、此前已允许分析的录像验证到EOF、source SHA/上下文/眼位输出；不全量重排既有录像。
6. 核对本人录像不占100盘高分局额度，达到100只停止新增高分下载，已下载分析继续；录像与分析报告两个数据目录及.state位置保持。
7. Insights端再核对catalog/报告读取与新记录交接；Foresight不自动重新承担Pi管理。后续何时停用旧调用需另行确认实际部署结果。
