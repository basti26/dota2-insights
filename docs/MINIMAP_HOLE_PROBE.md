# 小地图封闭颜色形状复核

2026-10-26。继续研究空心图标与小点、名字笔画的区别。这里只测量原图的封闭颜色空洞，不把它命名为“英雄圆环”，不变更颜色基线、候选删除或线上提示。当前资料已经用于探索，不能再称独立验证集。

## 度量

dota2_insights/minimap_hole_probe.py复用既有颜色范围和文字/方块重合证据，在原始颜色掩膜上提取带子轮廓的外层轮廓，不先做补洞或闭运算改变拓扑。

固定372px参考尺度，外接矩形最大边8–28px、最小边≥4px、长宽比≤3，轮廓面积≥12、圆度≥0.2。度量外轮廓填充区域中的实际非颜色像素，要求空白占比0.05–0.85；最多保留128个特征。输出包括原像素框、轮廓面积、空白像素数/封闭像素数、空白占比、孔洞数、圆度和文字/方块重合。

细边框不能直接使用子/父轮廓面积比：子轮廓包含边界像素，单像素笔画时会产生偏差。当前改用填充外轮廓内实际空白像素，生成9×11单像素矩形的独立期望为99个封闭像素、63个空白像素；该测试通过，参数范围没有根据真实裁片放宽。

颜色只有显示含义，不代表敌我。孔洞、圆度或text_band_overlaps为空均不能证明英雄身份；所有feature的hero_id=null、hero_or_glyph_or_other=unresolved，hero_count=null。

## 工具

```powershell
python tools/probe_minimap_holes.py --latest 3 --max-runs 2 --max-crops 48
```

入口先重新同步并复验新旧记录，以连续窗口模式准备每run最多24张原图。再次核验PNG SHA及尺寸，然后计算形状。按显示颜色、文字带重合与归一化大小分层，轮转抽取并沿帧序分散选点；不同长度分组使用各自固定队列，避免引用最后一个分组。max-runs限定1–3，max-crops限定1–96。

输出位于diagnostics/minimap-hole-probe/<UTC>/REPORT.md、report.json、sheet-*.png和crops/。裁片按原像素保存，报告绑定原图SHA、原行SHA、原框、裁片矩形和PNG/RGB像素SHA；拼图才按最近邻放大。源文件只读，处理期间图像或批次变化拒绝成功输出。算法源码SHA与参数SHA保留，未标注身份或训练真值。

## 结果

实际两条已有闭合流的48张不同SHA原图，提取300个封闭颜色形状，70个与疑似文字带重合、0个与实色方块形状重合，无128个上限触顶。分层准备48张裁片，已实际查看全部三页拼图。

可以明确看到文字封闭笔画、蓝紫色图标/装饰和绿色空心菱形图标都进入了结果。裁片2、5、9、23等可见文字笔画但文字带重合为false，说明“没有被文字带规则标到”不能作为安全排除文字的依据。绿色空心菱形只记录其外观，不认定它是英雄、眼或其他游戏对象；多个连续帧同一形状也不是独立目标。

因此当前孔洞特征可作为观察维度，但不能单独解决身份、人数或消失预警，更不能以0个方块重合宣称没有建筑/其他符号干扰。其余230个未标文字带的特征仍未知，不自动改成英雄。此次没有根据裁片结果收窄为“单孔就是英雄”规则，也未过滤旧候选。
