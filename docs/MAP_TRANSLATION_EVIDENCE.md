# 录像坐标平移的静态对象直接对照

2026-11-05。接续地图独立评估，将Gem原始坐标与资产实体世界坐标直接比较；不使用截图、像素窗口或坐标最近邻配对。

## 配对与准入

新增map_translation_pairs和compare_map_translation工具。输入为明确列出的最多8场开发比赛、已有静态对象提取结果、原始DEM、冻结资产实体导出及地图revision。

- 在读取提取正文或DEM载荷前，根据小清单检查每一个比赛的封存锁；读取DEM小型索引尾部的实际比赛号后再次检查。比赛重复、未知或身份不一致拒收。
- 提取记录须是固定gem版本/提交、明确的cell128+vec原始坐标、0–1秒静态观察窗、无解析错误且来源未变。原始DEM字节数/完整SHA和尾部比赛号进入、退出核验。
- 地图资产须与冻结revision身份相同；编译实体资源SHA必须出现在revision资源清单中，DATA文本及COMPLETE均复验。读取当前提取器解析原始DATA，明确包含塔，不借旧图像拟合值生成世界点。
- 仅支持塔、基地、瞭望塔；根据显式targetname和实体class一对一关联，资产只剥离已知编译前缀`[PR#]`。同名、多实体、类不符、阵营矛盾、非有限位置拒收；缺同名对象记为unmatched，不按位置补匹配。
- 固定比较`(-16384,-16384)`和`(0,0)`，不拟合平移或窗口；保留每一行原始XY、资产XYZ、来源、实体index/serial及原始名称。
- 所有输出使用新目录；来源与执行源码指纹退出复验后写COMPLETE。历史提取不覆盖、原始DEM不移动、坐标不回写。

示例：

```powershell
python tools/compare_map_translation.py --manifest diagnostics/<实验>/inputs.json --landmarks diagnostics/<实体导出目录> --revision diagnostics/map-versions/revisions/<revision-id> --output diagnostics/<实验>/<新输出目录>
```

manifest为schema_version=1、role=development，matches内每条包含match_id、extraction路径及extraction_sha256、原始replay绝对路径。提取记录和清单仍限定在本仓diagnostics或配置的历史根；原始DEM只按显式路径读取、上限512MiB，不枚举或自动解析历史全集。

## 实际证据

本轮在已准入的两场旧比赛上，各有界复算到开局第一秒内，耗时约1.27秒和1.11秒。52条静态记录与对应旧提取逐字段完全相等，原DEM的完整SHA与比赛号再次核验。它们来自同一批26个实际位置，不能当作52个独立空间位置。

每场包含22座塔、2座基地、2座瞭望塔。按名称精确配对的全部26个对象，在固定-16384平移后，XY最大差异约0.015845个世界单位。零平移的残差约23170世界单位。逐行差异完整保留，不取整、不补零、不剔除残差大的对象。

这直接支持：**这两份录像提取中的这些静态对象，采用-16384平移可以与该资产的同名对象对应。** 小残差与数值量化的量级相容，但没有另外证明其具体产生机制。

它不证明旧录像的整个地图包与当前包相同；录像MapIdentity保持未知，不能按26个坐标一致回填版本。也不证明GSI的坐标原点、碰撞模型放置、地图图片窗口、地形高度或真实眼位像素位置。P2/P3、生产状态和全局默认变换门禁保持未通过/关闭。

本机证据：diagnostics/map-translation-20261105/，当前结果compared-final/report.json；reproduction-check.json比较新旧52行，verification.json记录完整回归及来源复验。

## 接下来
