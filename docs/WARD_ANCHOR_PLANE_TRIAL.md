# 三条实测边界线加本人锚点：条件平面与旁路记录

2026-11-06。沿用先读图、自动留证、自然对局的路线；本批不操作游戏，不联网，不解析整场录像，不替换当前眼位显示矩阵。

## 数学路线与验证

ward_anchor_plane以三条实测直线（左、右、下）及同帧本人世界XY/画面点构造条件平面。左/右与下边的交点，加左右线的消失点，构成射影三角形；本人点约束其剩余比例。侧边上端只用来定义直线，不再当作完整视口上角。

生成的已知相机在1080p/2K下，用未参与拟合的三个世界点检查，误差约1e-6像素以下；可见侧边的上端从画面250移到700，恢复的完整平面保持相同。缺点、退化、锚点在边界、跨地平线、视口发散或可见端点落在视口外时拒收。这个结果证明代数在假设成立时正确，不证明Dota实际三边对应完整客户区。

## 实测线与默认模型分开

已有遮挡检测partial_outline能给默认模型，但模型点不是实测边界。因此新增measured_lower_lines：在已强支持的下边/两侧下段附近，只取实际青色掩码像素拟合直线，要求像素数量/跨度和残差，保留归一化端点及质量。

默认模型的上角仍标geometry_inferred，实测下边/侧边另存；只有三条线都满足要求才供锚点候选使用。旧camera_outline的三边实测路径也可供候选使用；四边或未知布局不混入这个三边解法。没有线就保留失败，不把默认角点直接升级成观测。

## 旧实战帧结果

先同步本机已有记录，按闭合收据/源SHA/封存策略准入最近5份眼位包；找到80张同时有本人GSI坐标、候选画面锚点、原生同帧图片和有效时间的保存帧，按预定等距位置选择8张。图片原字节复制到忽略的诊断目录，非新采屏，来源进出复验。

生产WardTerrain在8张完整原尺寸JPEG上均成功配准小地图；没有注入ROI。最初没有足够实测三边，补下部线测量后其中1张可建立条件平面，另外7张保持缺少三条边。

这1张在拟合锚点上残差约2.7e-12像素，但它不通过上一批“客户区中心主点/方形像素/完整Z0视口”的正焦距检查。没有用该残差宣称准确率，更没有把它投入显示。画面锚点在该资料里仍是头像/血条推算脚底，身份与脚底未认证；三条小地图线是否对应整个客户区（尤其HUD影响）、真实主点和参考地面均缺独立证据。该反例保留，不能靠调整HUD比例、脚底偏移或宽高来迎合焦距结果。

## 自动记录已接入

Foresight正常观察的既有Alt/诊断窗口中，若同帧有新鲜本人坐标与画面锚点，则计算anchor_plane_candidate；缺失也记录原因。保持原取帧节奏、原显示矩阵、容量/图片上限，不额外移动或操作游戏，不新增选项。

候选保留版本、三边/锚点来源、原始矩阵、条件视口、拟合残差及各未验证标志。actual main world_to_screen不换成候选。新ward_anchor_plane模块加入WardEvidence生产源码指纹。不要把旁路候选称为应用到Tk的显示结果。

Insights接收候选时验证版本、状态、矩阵有限性、本人坐标/GSI姿态/时间与锚点一致、数学残差和未认证声明；来源变化、陈旧、虚假认证或错误残差拒收。分别统计候选原因和条件式相机恢复结果，最多8个摘要例子。缺少新字段的旧包继续兼容。重建旧帧事件包用于诊断，不当作新的UI回执。

## 后续方向与完成边界

算法能形成条件平面，但现有真实样本尚不支持直接用作已校准镜头。下一步应寻找独立的视口或地图结构对应，区分真实地面点与血条推算点，核对小地图三边对应的实际渲染区域。新自然对局会自动补候选/实测线/失败字段，不要求用户专门开局。

不把拟合点本身当作独立验证，不把无正焦距解释成某个已确定的Dota内参，也不根据结果擅改主点/方形像素假设。当前主画面仍沿用试用链路，Z仍未用于改变落点，完整重叠继续未完成。未部署Pi、打包或提交推送。
