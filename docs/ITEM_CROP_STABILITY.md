## 自动报告的证据单位与重复关系

`probe`新增`evidence_units`，页面直接区分角色条目、源行（包ID+行号+行SHA）、裁片字节SHA、参考/目标字节对。保留所有首/末角色，不把不同时间的同像素记录合并；只标出同一事件/同源行/同裁片的角色别名，以及同裁片字节在不同源行重复的关系。以上都不是独立试验数，不能用作识别准确率分母。

准备裁片的源行号必须为正整数、行SHA必须完整有效，缺失/布尔/无效标识拒绝生成报告。它只检查准备资料中的证据绑定，不重新认证原始记录；original_sources_reverified_here继续false。未知角色数量的旧字段unknown_role_crops为兼容保留，其含义是角色条目数，实际不同字节数用evidence_units.distinct_crop_bytes，不混用。

实际`diagnostics/item-stability-20261029/probe-v3/`：38角色条目、25源行、25不同裁片字节、26参考/目标字节对；12组同事件同源同裁片角色别名，1组裁片在两个不同源行出现。相同像素不等于同一次观测，源行也不等于独立试验。与probe-v2逐条相似度/控制样本结果及输入SHA完全一致，见comparison-v2.json；本轮没有调整算法、门槛、识别标签或金额。旧原图、旧报告和实时Foresight均不改。

## 离线探针

```powershell
python tools/probe_item_crop_stability.py --evidence diagnostics/<新准备包>/evidence.json --evidence diagnostics/<另一准备包>/evidence.json --output diagnostics/<新探针目录>
```

输入只接受当前版本equipment_continuity_evidence、来源曾经进出复验标记、唯一package及角色。先检查封存身份，再读取目录内固定命名裁片，逐个核对原裁片SHA；页面/数值输出前再核对元数据及图像原字节。这里重新核验的是准备副本，原始游戏记录的最近准入发生在裁片准备阶段，不把元数据声明当成原源永久授权。

算法固定：灰度96×72；整幅相关性另列；取参考内区80×56，在目标图固定±8像素范围做归一化相关匹配。保留同一内区零平移NCC、最大NCC、位移和差值；不用不同面积的相关性差来假称平移收益。常量/低方差图返回无可比较值，避免OpenCV常量模板退化到伪满分。

同时与同包其他记录物品的已知裁片作数值对照，保留前三项。它们只是其他记录标签的对照，不是完整负例真值。38角色中本事件前帧的相关性均高于所取对照（最小差0.141），但这些是已按“先known再unknown”定向挑选的样本，绝不据此计算召回率/误报率/阈值或发布在线规则。

输出probe.json、可离线打开的index.html。实际证据diagnostics/item-stability-20261029/probe-v2/含两组示例图examples.png及绑定原裁片SHA/原日志行SHA的visual-review.json。visual-review明确reviewer_kind=assistant_visual_inspection、independent_truth_available=false；未回写原记录或自动进入训练/线上金额。
