# BP生成与应用链路诊断

`dota2_insights/draft_diagnostics.py`从已核验的BP结束阶段前缀提取选人事件、冲突槽位、推荐候选数、等待原因与已有耗时。由`draft_phase_handoff.review`在同一个进出复验上下文调用；不读封存尾部，不补人工身份或改变线上推荐。

已确认阵容沿用公开槽位语义：英雄非空、public=true且无conflict；有名字但冲突的槽位不算确认。己方屏幕侧未知时双方数量保持null。raw_hero_slots另列，不用它判断2+2已满足。

UI应用仅在完整snapshot/advice一致、日志UTC有效且只有一个先行事件时关联；相同revision不够，多个相同先行事件不挑一个猜延迟。负时差/无时区时间/缺回执均未知。写入到控件应用的毫秒不是头像首次出现到显示延迟，也不证明OS实际呈现或用户已看到。

日常入口`tools/review_recordings.py`写入同份复盘报告，单前缀CLI也输出diagnostics。无UI流显示未知，不判为推荐失败；截点之前缺回执不推断后续发生什么。

## 自动复盘中的各轮时序（2026-10-29）

`stage_timing`及中文“BP各轮记录时序”表按日志区分首轮和末选。资格基于当条公开无冲突阵容：己方恰好2/4人、敌方至少2/4人；不把冲突头像、最终阵容或未知我方侧回填成已满足。首个结束阶段之前分别查首条满足条件的事件、同轮非空推荐和完整视图唯一先行事件的控件回执。控件可以对应后续更新，不假设一定对应第一条推荐，保留来源事件行和surface。

独立事件之间UTC有效且不倒退才报告日志间隔；资格与推荐在同一事件时显示“同事件（非耗时）”，不写成推荐计算0毫秒。所报控件间隔依然从事件写入开始，不是英雄头像首次可见到用户看见的端到端延迟。首个strategy/in_game/post_game事件只能作为记录结束参照；缺失/无效结束时钟保持未知，即使有事件也不认证OS显示或隐藏成功。

最新三份前缀共六轮均有非空推荐，但两份没有ui-presented流，另一份只有首轮一条game_panel回执，记录差88毫秒；全部缺panel-visibility流。不能据生成成功认证“每轮推荐可见”或“选人结束已退场”。证据`diagnostics/bp-stage-timing-20261029/REPORT-v2.md`与`reports-v2.json`，通过各自前缀/绑定SHA准入和退出复验，不读截止后的尾部。

后续自然对局的生产端留证需求：覆盖实际使用的融合栏/游戏面板surface，在控件应用和显示/隐藏执行后记录明确会话、阶段、推荐视图标识、执行时钟、动作与原因。阶段退出尤其需要隐藏完成或失败回执；仅有结束事件不能替代。补有限关键帧时绑定原帧时间/图SHA与该动作，不能把截图申请当作成功采样，也不能用控件回执认证像素。记录先做好，再等用户正常对局，不安排现场重演；Foresight实现另行维护，本轮未修改其源码。

## 已有显隐流的自动消费

生产端已有`panel-visibility.jsonl`，不能笼统称其记录功能完全未做：近期三份前缀缺该流，而此前Insights诊断也没有消费这条流。现由同一`DraftDiagnostics`在前缀进出复验范围内读取，报告`panel_visibility_evidence`和“面板显隐记录”表，无需第二套接收协议或跨仓导入。

每行保留原行SHA、时钟、阶段、revision、visible/expanded、reason和明确display_mode。v1、会话形状、布尔类型、原因与visible一致性、模式枚举及具时区的观察/写入时间顺序不合格时单列invalid_widget_flag；不把无效行当隐藏或健康。0 revision与false保留。缺流、明确空流和未声明是否有流分开，不将缺流记成0次隐藏。

旧行没有display_mode时保留legacy_default_not_recorded，不凭默认bp认证当时展示了BP推荐。显式laning/roster不当作BP；只有显式bp且在strategy/in_game/finished阶段visible=true的行进入待查列表。列表仍只是控件标志证据，不自动判定用户看见了过期推荐。字段不按revision单独拼接推荐/结束事件，也不会使end_widget_hidden_verified或OS呈现认证变为true。

该流现有模式是显示意图，且没有完整surface/视图身份与OS像素证据，不能代表融合栏等所有界面的显示完成。未来记录仍需补实际surface的动作回执及关键帧；新分析器不会替旧资料补字段。生成前缀测试已验证截点后非法尾部不读，显隐字段由原行SHA绑定；实际旧前缀的覆盖核查结果另存诊断目录。

本轮实际有界同步最多12个前缀，发现并准入9份，逐份前缀/绑定SHA及退出复验通过，全部缺显隐流。`diagnostics/bp-visibility-20261029/REPORT.md`将这些缺失显示为未知而非0次隐藏；`reports.json`和`index-reviewed.json`保留索引SHA/原行证据。此结果不证明完整日志尾部或其他未准入目录也没有记录。45项BP相关检查及782项完整离线回归通过（run-00ee4609ade4/run-ccd1db4dcd89），失败/错误/跳过/后台异常均0、源码稳定。后续已有流可自动分析，真实显隐行仍缺；不因此声称生产端或OS验收完成。

## 推荐当时的数据依据审计

日常 `tools/review_recordings.py` 的统一报告包含“BP推荐数据依据”，每个阶段取第一条选人期且含候选的事件，展示前三名。JSON中每条事件都有advice_data_health，保留当时cache_status、bundle ID/SHA、统计scope及能力规则状态/版本/SHA；这些是原记录字段，不是对当前缓存或当前游戏补丁的独立验证，未知字段不补齐。

对阵分母仅来自本事件公开且无冲突的英雄格，按own_side分为with/against；缺阵营或重复英雄时关系分母未知。不用最终阵容、下一次快照或当前缓存回填。每个预期关系要求唯一记录、正整数match_count与有限delta；0差值有效，缺失、重复、无效样本分开记录。默认低于100场只标为小样本，不能据此断言克制不成立。原unknown_relations保留，和重新按公开阵容计算的结果不混为一谈。

关系覆盖不代表胜率或delta真实、推荐有优势、规则适配当前补丁或用户实际看到推荐。审计只读已准入的BP前缀，与原始行SHA及包身份一同保存，不访问外网或改变实时评分。
