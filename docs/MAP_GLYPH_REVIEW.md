# 已有地图图片的图标核对

仅离线读取已采集地图图像；原Helper历史只读，输出留在Insights。先运行observe，生成并固定observations.json及SHA；再运行compare读取冻结坐标模型。两步不能合并成按预测点附近搜索。需要本机history.local.json配置历史根目录。

```powershell
python tools/review_map_glyphs.py observe --package <历史package-v4目录> --icons <历史icon-reference目录> --output diagnostics/<新观察目录>
python tools/review_map_glyphs.py compare --package <历史package-v4目录> --batch diagnostics/<新观察目录> --output diagnostics/<新比较目录>
```

使用已提取的官方图集和mod_textures命名定义裁出莲花池、瞭望塔、赏金符及未知符图标。原生小地图整图搜索，NCC阈值保持0.92，预设尺寸从旧12–32扩展为8–32像素；不根据预测偏差调整阈值。比较前核对完整15帧×4图标名册、图像绑定和冻结SHA，重复/缺项/换图拒收。数量不一致、候选溢出或集合对应歧义保留无法判断。

神符两类模板各自与四个神符出生原点作集合探索，不能先验认定赏金图标一定对应强化符原点；计数或集合相容也不证明命名实体身份。实际物品图标可能随游戏状态改变，不能把漏检直接认定为坐标错误。

检测器由拆仓前minimap_icon_probe的整图NCC实现改编；参考原文件SHA256为73a43366e520e9c72679f34f1511d60239fee186fa028d1d2e21c342fbe4197b。新文件独立存在于本仓库，没有跨仓库运行时导入，也不声称与原模块逐字相同。素材与检测时源码SHA保存在本机观察文件；原模型和旧观察不改写。
