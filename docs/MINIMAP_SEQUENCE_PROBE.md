# 小地图连续窗口与图像候选对应

2026-10-26。连续画面用于研究静态符号、文字和移动标记的歧义，不生成英雄轨迹、消失事件或线上预警。已有单帧文字/方块规则不调整、不删除候选。

## 取样

```powershell
python tools/probe_minimap_sequences.py --latest 3 --max-runs 2 --max-images 24
```

先复用prepare_minimap_review，重新同步并复验来源，然后以continuous_windows模式在每个run约1/3、2/3及最大采集间隔附近各取一个连续序列。24张预算时每窗口最多8条样本；窗口可能重叠，样本先去重保存，同一条可以属于多个窗口，统计不得称为独立对象。小run、重叠窗口或不可用图像不补假帧。

取样仍绑定原行SHA、原PNG及原BGR像素SHA、客户端/ROI尺寸；原生与旧格式均走原有进出复验门禁。输出在Insights diagnostics，旧文件只读。原有分散抽样模式不变，可单独用prepare_minimap_review.py --selection continuous_windows选择新模式。

## 两帧比较门禁

dota2_insights/minimap_pair_probe.py只对序号和样本序位都相邻的两帧比较：图像尺寸相同，client_size/roi/layout_segment/time_basis已知且一致，ROI尺寸与原图相符，原采集UTC严格前进且间隔≤1.5秒。缺图导致的跳号、布局变化、时间倒退/重复/未知、较长间隔均不可比较；颜色候选超过48个而被截断时也不可比较。

基础候选继续用已经独立对照的颜色/轮廓算法。两帧同色候选归一化距离≤0.035，并且双向都只有一个可能对应时，才记录一条图像对应；多对一/一对多不任意选最近项。不建立跨窗口身份、不把新候选分配成英雄、不把没有唯一对应称为消失。

距离≤1.5×min(图宽,图高)/372像素记small_displacement，较大者记larger_displacement，仅表示像素位移。站定的英雄可以是小位移，兵线/文字也可以移动；图标边界变化、文字合并或背景光效也会影响对应。两帧任一方有文字带/实色方块重合则保留该标记，仍不分类或删框。全图像素差异比例只作为图像现象，不表示游戏状态变化量。

## 输出

REPORT.md、report.json，以及window-*/window.json、contact.png、preview.gif和pair-*.png。连续拼图显示原样本序号/原采集UTC；对应图浅蓝表示小位移、橙色表示较大位移，均不是敌我或英雄标签。GIF固定每帧500ms，只供观察，不能当真实速度/游戏回放；比较使用记录内原UTC。原PNG仍在关联的minimap-image-review输出中。

报告记录每一对比较的原行证据、门禁状态、位移及重合。没有唯一对应的前后候选数量不是“英雄消失/出现人数”。英雄数量/身份/预测准确率维持未知，online_changes_applied=false。
