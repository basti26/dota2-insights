## P1：数据模型

实现dota2_insights/virtual_map.py，纯数据和数学，不加载游戏资产或显示库。

- MapIdentity：地图/地形变体名、客户端构建、地图包SHA、可空玩法补丁。已知版本/包/变体不同默认拒绝，不因看起来相近静默复用；跨构建同包兼容以后须单独提供显式依据。
- WorldPoint：X/Y、可选Z、身份和坐标框架。原始点不改写；Z保留在主数据里，二维逆变换不制造地面高度。
- 三种框架分别命名：source2_map_centered、gem_cell128_plus_vec_raw、gsi_hero_world。未确认GSI与地图原点相同前不设隐式别名；转换需要显式TranslationCandidate、版本/来源和未验证许可。
- WorldBounds：有限且非退化的四界。不能依据离群点自动拉伸或把超界点夹回地图。
- VirtualMap：world_to_norm与norm_to_world，全局约定世界Y向上、归一化V向下。NormalizedPoint携带model_id，不允许不同bounds的归一化点直接混用。
- model_id覆盖身份、bounds、坐标框架和来源。v1只有unverified候选状态，默认变换调用拒绝；离线诊断须显式allow_unverified=True。仅数学回环通过不能写成P2已通过，序列化伪造passed状态会拒收。

允许显式诊断超界点，输出真实的区间外归一化值，不裁剪、不移动它们。原始点和观测证据可长期保存；显示时的派生坐标以后由单独视图变换处理，截图像素及变换来源留作证据，不写进世界模型主坐标。

## 审计工具

```powershell
python tools/audit_virtual_map.py --game <安装目录>/game/dota --output diagnostics/<新目录>
```

可选--previous-inventory指定以前有来源SHA的地图包资源清单。工具只读本机VPK目录和少量明确编译资源，逐资源CRC/原字节SHA及头部块范围核验；结束时重验整个地图包和steam.inf。Dota运行时拒绝，不调用游戏、不联网、不操作窗口。

输出audit.json和candidate-models.json，仅在被Git忽略的diagnostics内。游戏资源二进制、导出模型、纹理和地图图片不进入仓库；本轮没有发布任何游戏资产。当前具体证据为diagnostics/virtual-map-20261105-current/。

## 下一步与自动记录需求

P2先冻结留出非塔地标清单，训练与验收不重合。每条需要map_asset_sha256/构建/地图变体、明确坐标框架、原始世界XYZ及来源、底图/截图字节SHA、独立图上位置和确认来源、训练或留出标签。存在截图时保留原尺寸、有效内容框和显示变换标识，不能用同一模型先生成标注再验自己。

1024参考尺寸median≤4、p95≤10暂作预设尺子，中心/四边/四角分别报告样本数、缺失和分布；缺少某区域不补零，不以总体值通过代替边角验证。底图或坐标语义不同时先拒绝混合统计，不由显示层调参消除数据层误差。现有树/塔/巡图/地标候选可整理，但未经独立确认的观测不能冒充留出真值。

需要新增游戏证据时先按上述字段设计有界自动留证，使用用户自然对局或既有录制；不要求专门开游戏/回放逐点验证。P2未通过之前保持候选，不进入生产投影调参。

地图模型下一步可优先研究world_physics中的三角面与坐标变换，建立多层地表/悬崖结构；模型包围盒不是可玩边界，碰撞三角形也不是已认证地面高度。即使有正确XYZ，游戏画面投影仍需要镜头位置、方向、缩放及视图变换；读取离线资产不会自动解决镜头漂移。
