# 本机镜头与 HUD 资源核查

2026-11-06。本批只读取安装资源和已保存设置，不启动游戏、不采屏、不修改游戏配置。

## 已确认的内容

对本机 pak01_dir.vpk 中的 hud_reborn 样式、布局及两份 minimap 脚本做有界提取；编译资源 CRC、SHA、目录 SHA 与重复解码输出均记录在忽略目录 diagnostics/camera-resource-probe-20261106-v2/probe.json。最终重新核对四份提取资源的 SHA，两个解码文本与重复输出逐字节相同。早期不带 v2 的目录为保留的失败尝试，不作为成功凭据。

HUD 样式包含 minimap_block 的 244×244、minimap 的 260×260 等布局尺寸。这些是 UI 布局单位，不直接等于原生截图像素，更不能当作主画面世界视口边界。布局内出现的 cameraOrigin、lookAt、fov 属于肖像、粒子或代币等独立场景面板；不能用它们标定游戏世界相机。

另检查 Steam 本机 26 份有界设置文件，其中 4 份含镜头或 HUD 键；只导出相关键值和来源 SHA，不复制账号名、路径或完整配置。保存的 fov_desired=75 是待核对线索，不能证明当前世界相机实际采用该 FOV。不同保存范围存在大小地图、翻转等相反值，未选择当前活跃账号，不把这些设置的并集当成运行时状态。配置来源读取前后字节相同，收据为同目录 config-probe.json。

## 本批不能解决的内容

尚未取得当前世界视口矩形、主点、实际投影矩阵或独立脚底坐标。资源核查不能解释三边加本人锚点试验中无正焦距的原因，不能证明问题来自 HUD、脚底偏移或非方形像素中的任何一项。

因此不硬编码 75 度，不根据 244/260 等比例裁掉画面底部，也不从 UI 粒子相机借用内参。Foresight 继续使用已接入的虚化眼试用链路；条件平面仍只记录，不替换实际显示矩阵。相关实现与已有专项回归见 WARD_ANCHOR_PLANE_TRIAL.md；本批无算法变更，不重复运行测试。
