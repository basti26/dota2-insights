# 录像原生高度记录与候选坐标证据

2026-11-06。继续地图重叠计划：从原生录像实体补齐高度字段，减少仅从平面XY猜地面高度的依赖。没有开游戏、采屏或联网，没有修改Foresight覆盖层，没有整场重解析或部署Pi。

## 找到的缺口

本机固定gem-dota0.13.0的_pos只读取cellX/cellY/vecX/vecY；我们的英雄、建筑与眼位导出也只保留XY。实际录像实体还有CBodyComponent.m_cellZ、CBodyComponent.m_vecZ，属于被导出遗漏的原始信息。新适配不修改第三方库。

## 已实现

- replay_height.height_observation：白名单读取两个原始Z分量，raw_z=cellZ*128+vecZ，记录原始分量、状态和来源坐标基。0是有效值；缺失、布尔、非有限和超预算分别保持未知/无效，不回填0、不强行把vecZ归一化到128以内。centered_transform_verified和ground_height_verified保持false。
- 建筑初始锚点、建筑实体前缀和英雄归档样本新增可选height_observation，不修改旧XY/经济字段。原始高度与源实体原点绑定，不称地面高度；建筑前缀去重也考虑高度变化。
- 眼位在原生_on_entity回调生成新的WardEvent时，绑定这个确切事件对象与同一实体index/serial。即使同tick/同XY有多个事件也不猜关联。一个回调产生多个新事件则记歧义，超8192条停止补高度，无法关联保持未知。眼位高度采样点是原生放置回调，不冒充完成包末尾采样；英雄/建筑则继承父记录的完成包语义。
- 眼位清单增加高度采集版本/限额/歧义与适配器SHA；建筑/英雄清单也保留适配器SHA。便携构建和固定Pi建筑作业的源码清单已补新依赖，Pi部署闭包自动包含此模块。没有实际打包新EXE或修改Pi服务。
- 初始建筑提取入口在依赖/游戏探测前拒绝已知封存路径，并在完整hash或解析正文前核对独立footer身份。已有封存名单不改。

## 有界真实资料结果

使用之前已准入的同两份本机录像，只重读开局第一秒附近的26个静态建筑位置，每份约1.1秒解析，独立footer及完整原DEM SHA进出核验。

52条记录、26个不同命名对象；所有旧字段逐项一致。固定候选raw_z-16384与同名地图实体原点Z对照，median=0、p95=0.031128、max=0.031189世界单位；未拟合offset，零平移的中位差约16384。该证据只支持这些同名建筑，不直接认证全局录像地图版本、GSI高度、任意英雄/眼位的高度语义。

再对其中一份录像做开局至60.0333比赛秒的短前缀（非整场），6次原生放眼均关联到确切实体且高度已记录，前缀末尾10名英雄均有原始高度字段。6个眼位的候选中心XYZ与当前普通碰撞交点比较，全部在0.05世界单位内有命中；保留所有交点而不是选最高点。因为录像整体地图身份尚未知，这只是条件比较，不据6个位置宣布全图贴地精度。

## 对地图重叠的意义与后续

现在可以记录眼位自己的原生高度，后续导出眼位参考包时应保留raw_z、来源和地图身份，而不是把实体origin或碰撞最高层直接当作放眼高度。英雄原始高度可用于赛后区分坡地/台阶样本，但飞行、跳跃和实体原点偏移仍需单独处理。

下一步：让Insights眼位参考包在明确身份与来源下保留高度，分析自然对局的镜头与高度误差，再确定Foresight的三维投影所需镜头参数。只有平面3×3矩阵不能凭空唯一确定三维相机；本批没有加入猜测的Z屏幕偏移，没有宣布完全重叠。GSI是否提供Z仍待现有原生记录核查，不能用录像有Z推断GSI也有。
