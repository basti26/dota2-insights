# 眼位自动留证 v2：原尺寸 JPEG 与跨阶段采样

2026-10-29。旧v1 PNG仍可读取，历史文件不转换、不删除。新Foresight写schema_version=2（事件和收尾清单一致），需要本批Insights接收；旧读者遇到v2应拒收，不能按v1猜读。旧EXE未更新。

## 调整依据

在三个已闭合的UI记录段中核验129张2560×1440 PNG的原始字节SHA和IHDR尺寸，共628.20MiB。段内未绑定的截图仍不按时间认定比赛归属。每段事先固定6个等间距行，合计18张做编码测算：PNG压缩3中位5,439,363.5字节，JPEG90中位879,236.5字节、样本最大1,175,026字节；本机编码中位345.30ms对9.20ms。测算顺序固定、只覆盖本机这些图，不是跨机器性能保证或游戏FPS对照。

旧PNG/15秒/128MiB方案按样本中位固定尺寸且忽略元数据的模型只能存约24张，约6分钟触顶；80张PNG即使不触顶也容易只覆盖开头。新的每分钟/80张策略计划图像时域约80分钟；按样本中位/最大JPEG尺寸计算，80张分别约67.08/89.65MiB，给元数据留出更多余量。实际覆盖仍受前台、GSI、容量、图像变化和正常停止影响，不保证完整一局。

## 新默认与图像语义

- 只改变眼位诊断留图：默认每60秒最多一张、最多80张、JPEG质量90、保持原尺寸，不缩放、不裁切。PNG仍可由构造参数image_format='png'显式选择。
- JPEG是有损诊断图，不是原始像素副本。每张image明确encoding.format/quality/lossless及width/height；收尾清单固定整段image_format、jpeg_quality、native_image_dimensions_preserved。
- 采集/ORB/RANSAC/投影使用编码前原帧；自动定位尝试仍最多每5秒、显示开启时沿已有2Hz，元数据记录上限不变。原生帧像素SHA只标声明，不把JPEG文件SHA当原始像素已验证。
- 2格后台队列、4096事件、2小时、128MiB硬上限及失败/丢弃/退出状态保持。上限会停止自动取帧，完整标志只代表本段写入收尾，不代表全局覆盖。
- 本人经济、装备/BP识别输入、原有field-visuals PNG记录及音频都不改变。

## 接收与兼容

Insights同时读取v1/v2。v1保留PNG旧格式；v2允许声明的PNG或JPEG，文件后缀、清单编码、逐图有损标志与原生尺寸须一致，混版本或把JPEG标为无损会拒收。所有文件仍按大小/SHA进出复验；接收器不解码像素，不自动认证原始像素或真实地图精度。

启动、明确来源/封存锁、闭合清单、严格原帧定位→Tk回执、未发布失败元数据诊断沿用[原留证契约](WARD_CAMERA_EVIDENCE_V1.md)。没有参考保持未定位；没有CLOSED不读事件/图片，不从状态文件判断进程存活。

## 离线证据与限制

成本证据在Insights diagnostics/ward-camera-storage-20261029/native-storage-and-encoding.json及sampling-policy-analysis.json，原始129张PNG与其索引都只读。额外对已核验2K原图做JPEG90往返，解码尺寸保持1440×2560×3；未做真实地图、文字可读性或颜色识别准确率认证。

生成的无参考/成功定位/初始化失败三类真实生产路径已以v2在独立Insights日常报告验证；真实ORB/RANSAC/投影继续使用原帧，生成平移恢复结果不变。旧v1的实际生成PNG包也已由当前读者重验。来源图与旧生成试验均保留，重复试验不充作独立对局。

没有启动游戏/真实采屏/录音、联网、Pi部署、重建EXE或Git提交推送；实战FPS、采样实际覆盖和地图精度仍待以后自然资料，不能从离线编码用时推断掉帧改善。

## 接收端损失声明门槛（2026-10-29）

Insights对v1/v2闭合包都要求显式的非负整数dropped、布尔limited/shutdown_timed_out及0–80整数images_saved，拒绝以null、0、false等跨类型替代或省略字段。检查在事件和图片哈希读取之前；缺字段不推定无丢弃。未发布段仍只走有界元数据诊断，不能据此认证正文或存活。26项专项及848项完整离线回归通过，旧PNG和新JPEG生成包兼容重验通过；这不认证像素或地图真值。
