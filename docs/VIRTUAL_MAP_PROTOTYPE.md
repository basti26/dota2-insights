2026-11-05。原型用于离线查看已有地图资源、地标与冻结图像的关系，附单盘职业眼位候选；不是通过P2/P3/P4的生产地图或游戏内浮层。没有改Foresight、启动游戏、采新画面、下载数据或重新解析DEM。

本轮“原型＋已有资料相互印证对照”已交付核验：启动入口、19份显示素材、交互记录及静态/图像候选对照逐项复查，当前366份源码与921项回归通过时一致。核验明细为v3目录的completion-audit.json；该结论不将下文尚未完成的全图认证、P2/P3/P4或真实游戏落点标记为通过。

后续地图更新已补独立接口，见[地图更新与版本资料接口](MAP_UPDATE_INTERFACE.md)。`check_prototype`可检查这份历史原型和当前安装是否一致；`capture/prepare/read_prepared`按独立版本保存并核验新资料，不改写v3原包或自动继承其标定状态。

## 当前入口

本机最新材料包为`diagnostics/virtual-map-prototype-20261105-v4/`，双击其中的“打开地图原型.lnk”。v2/v3原包保持不变，可继续查看。v4加入眼位版本绑定与时间筛选，见[眼位接入](WARD_MAP_INTEGRATION.md)。快捷方式只启动本机Python和本仓工具，不启动后台服务。也可在本仓根目录执行：

```powershell
python tools/map_prototype.py view diagnostics/virtual-map-prototype-20261105-v4
```

原型不是独立EXE，需要当前项目的Python环境。程序退出即停止，没有联网或游戏采集线程。v3的`overview.png`是同一渲染器生成的四栏对照图，未启动GUI也可查看。

## 怎么操作

左侧是实体世界坐标平面，黄框为资源声明的小地图窗口。滚轮缩放、按住左键拖动、单击地标；也可从下拉框选择26个地标。下方显示实体原始XYZ和对应截图预测，原坐标始终保留。

右侧可选15张已有巡图截图，覆盖白天/夜晚、天辉/夜魇及全视野场景。投影下拉框在“旧塔点矩阵”和“声明边界铺满截图”之间切换，两者都固定，不在线拟合。青圈为事先冻结的莲花候选，灰圈为其他冻结候选，十字为实体原点预测。瞭望塔候选含已知地形假阳性，不作真值；选中实体不等于已确认其图标身份。

“尝试同原点叠加碰撞”默认关闭。打开后绘制从当前静态碰撞模型得到的近水平面高度着色，明确是在试同原点假设，不代表世界放置变换已确认；颜色不是可走地面、精确深度或眼位合法性。

v3增加“GNV原始网格”和“TRM静态坐标”两个选项。GNV与碰撞底图互斥，方便按同一视图切换对照，网格颜色仅表示原始字节类别；悬停显示候选行列和十六进制原值，框外保持未知。TRM浅点为2484条静态XY/层记录，粉圈为9条没有与旧实体目录逐记录配对的差异；它们包括一条重复记录，不自动删除，也不等于当前存活树。详见MAP_ROOT_ASSETS.md。

“历史眼位候选”默认关闭。当前只收一盘已完成职业录像的41个放置点，绿假眼、红真眼；点击可看放置比赛时间、原始录像XY及候选平移后XY。保留原坐标，显示时显式使用(-16384,-16384)候选平移。录像地图版本及此变换仍未认证。这是全场历史分布，不是同时存活/玩家可见的眼位，也不是右侧巡图画面里的眼，故不叠到右侧截图。

## 模型与资料边界

世界实体标记只保存原始XYZ；显示使用已有`VirtualMap`候选模型做世界→归一化，再由显示适配器做归一化→像素。模型默认认证门禁未改变，诊断端显式允许未验证候选及超界显示。地图纹理与实体标记使用同一显示变换；图像原始观测的像素坐标作为证据独立保存，不写回世界标记。

碰撞局部坐标、实体坐标、录像原始坐标仍分开命名。只在用户启用候选层后做带明确标签的对照，不把它们注册成已认证别名。保存截图的边界、地图声明窗口和碰撞几何包围盒互不替代。

准备入口复验原碰撞/实体COMPLETE、网格归档SHA、窗口对照及其上游来源；巡图包按`map_holdout.read_plan`核验15张准备图。此前窗口报告对应清理unused import之前的源码指纹，原报告保留；已在当前源码重跑到`map-window-review-20261105/reproduced-v2/`，除来源指纹外的结果逐项完全相等，未忽略旧指纹不符。

眼位只消费已冻结的本地收集snapshot与receipt：先查显式比赛号及清单的封存锁，再校验快照SHA，只解码指定单盘，核对原始wards字节/完整EOF/解析身份/原录像SHA。未知地图版本保持未知，不访问Pi或扩大解析范围。最终原型manifest包含单独比赛号，用于在读取显示正文前做封存门禁；之后复核场景内身份一致，原始坐标不改写。

导出与显示素材仅保存在Git忽略的diagnostics。每次显示前校验manifest、全部显示文件与模型身份（v2为17份，含GNV的v3为19份）；缺失、改动或伪造P2通过状态时拒绝。没有把游戏图片、模型、用户资料提交进源码。

## 已验证与仍未验证

已验证的运行行为：26地标选择、15帧×2投影状态、40个缩放平移状态、41次实际眼位点击均能执行；世界坐标回环误差约7.28e-12单位，原地标/录像坐标不变。该误差只证明显示变换内部一致，不能作为真实地图或游戏画面误差。

资源交叉证据：6966与6971的地图包SHA一致，26地标原点精确相同。冻结莲花候选对比仍是直接铺满14.428～22.969px、旧参考0.266～0.411px（360px参考）；24个残差仅来自两个不同位置，不能认证全图。缺失候选不补零。

v3另有2475条实体树与TRM的XY/层精确配对，和1415条主地图依赖引用的双解析器一致；这些是静态资源交叉证据，不补作独立游戏像素标签或运行时身份认证。

实际材料界面检查收据为`actual-ui-verification.json`，使用自有隐藏Tk控件和真实显示素材，不是操作系统截图或游戏浮层验收。生成概览图已目视复查。首版910项完整离线回归后，v3最终921项通过，0失败/错误/跳过/后台异常、源码稳定，见`diagnostics/offline-tests/run-569e0912a880/result.json`；原型专项13项，连同根资源、清单和解码检查28项，包含身份门禁前置、原坐标不变、单一变换、图层控件和原始格查询。

仍缺：physics模型世界放置的直接绑定证据、跨区域独立非塔观测、录像眼位版本及真实落点核验、动态树木与可插眼语义。P2/P3/P4继续未完成，原型不放行生产投影。

## 复现材料准备

```powershell
python tools/map_prototype.py prepare --collision <碰撞提取目录> --landmarks <实体提取目录> --review <当前源码的冻结窗口对照目录> --survey <已冻结巡图包> --ward-snapshot <已收集快照> --ward-receipt <快照收据> --ward-match <明确单盘编号> --output diagnostics/<新目录>
python tools/map_prototype.py view diagnostics/<新目录> --export diagnostics/<新目录>/overview.png
```

三个ward参数可以全部省略，不能只传一部分。准备过程只读已配置历史根，新产物只写本仓diagnostics新目录，不覆盖旧报告。命令不生成新CMD、EXE或启动任务。

v3可另传`--root-assets <已生成root-assets.json的目录>`。来源地图包/构建必须与当前原型一致，4份根资源SHA全部核验才加入；不传则保留原来的三栏显示。
