# 自动经济复查闭环

2026-11-05。Foresight负责实时经济与证据、赛后编号及独立下载器；Insights独立进程负责赛后准入、解析、对照、报告。两仓不导入彼此Python源码，仅交换本机文件和进程入口。

## 日常行为

从已配置的Foresight源码入口启动助手后，独立复查后台自动启动。下载队列是持久赛后通知来源；未闭合的GSI/装备资料不能因队列中出现编号就准入。首次安装只补最近3场；之后新增编号自动排队，重启后去重恢复，不扫描解析整库历史。人机无正式编号时尚不能由该队列触发，继续保留原会话记录，不能声称其录像闭环已完成。

游戏进程运行时暂停，避免争用游戏资源。关闭Dota后后台每10秒检查、每轮处理一场；等待录像/来源的任务每10分钟复看本地文件。GUI退出只断开客户端，后台继续；Windows关机/注销后，下次开助手恢复，未安装开机服务或计划任务。

1. 独立同步最近64份原生GSI/装备索引，并对同一明确比赛号的闭合包逐个进出复验。缺失、封存、冲突、未排空与改写的包不准入。
2. 自动生成本人GSI分项检查、装备未知/高价候选、大件known→unknown中断以及带原图SHA/源行SHA的优先和四阶段图片。GSI原值不平滑，不给未知补零。
3. 没有同场录像时先发布记录报告，状态为缺录像；不会阻止记录复查。若闭合来源本身没齐则明确等待来源，不把空输入判通过。
4. 录像后来出现在助手下载目录或配置的游戏录像目录时，自动升级为录像复查。只处理排队比赛；1Hz、最多600秒/256MiB，低优先级、低磁盘余量拒绝，新游戏启动检查并终止解析子进程。中断/解析失败仍保存已完成的记录报告，按退避重试。
5. 固定比赛钟±1秒、邻近GSI差≤1秒匹配；未知、缺时钟、暂停歧义和2000帧上限分别留痕。大件未知候选单列，不以连续重复观测作为独立错误数。最多首60个差异帧保留固定±3秒窗口和最近过去可见库存候选，不用物品相似度挑时刻，不用未来帧补实战库存。
6. 仅在来源上下文退出复验通过后发布报告；输入包/录像状态与本流水线源码指纹不变时复用现有报告。旧报告保持原生成时间，不冒充重新认证。归档数据修改应重新准入，不修改原始资料。

自动完成的是程序能核查的证据链。图像真值、敌方HUD最后可见库存的因果解释、合并眼实体语义、精确同tick/真实UI像素和完整净资产仍需独立确认；报告不会因流程跑完就写准确率通过，也不自动训练或降低实时门槛。

## 配置与入口

本机历史目录继续使用Git忽略的`config/history.local.json`。可选`config/automatic_economy.local.json`沿用example字段：replay_directories为允许自动寻找同编号DEM的绝对目录；archive_directories为Insights自身diagnostics内已有完整解析目录，最多32个，用实际DEM SHA/解析身份及样本SHA重新验证后复用，避免重复解析。配置不进Git。

入口`tools/automatic_economy_review.py --service`；`--once`为维护/离线检查的一轮入口，不新增CMD。普通用户由Foresight启动，不需要逐局运行命令。

输出`diagnostics/automatic-economy/queue.json`、`status.json`、`index.html`及`matches/<比赛号>/<修订ID>/`。报告修订保留JSON、Markdown、HTML、图片及有界解析日志；旧文件不自动删除。单实例文件锁由OS释放，异常退避从10分钟增加至最多一天，容量1000任务/10000已见编号，触顶明确报错，不默默丢任务。最近64份来源窗口之外的积压会保持等待，未宣称无限历史自动追溯。

下载器独立，不依赖Insights；仍是赛后10分钟、Dota关闭后尝试一次，没有地址就manual_required。本任务不重置失败任务、不反复向外网请求、不替用户登录Steam。手动游戏内下载到指定目录后，后台会接续处理。

## 验证口径

生成夹具覆盖真实闭合包准入→记录报告→缺录像→补录像→对照完成、来源改写拒收、队列重启去重、有限近期补查、游戏门禁/终止子进程、解析失败保留报告、实例互斥。测试不接触游戏、真实设备或外网。

自然新局的赛后通知→闭合交付→自动下载→录像对照整链仍需自然记录确认；已有真实记录的独立后台运行另存本机证据，不用旧人工报告冒充自动执行。
