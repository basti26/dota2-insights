# 冻结音频候选的分层复听

`tools/prepare_audio_candidate_review.py`把已完成盲测中的候选导出到新的本机复听包，不重新识别、不读取GSI标签、不改原预测或自动训练。

参数：`--run <原录音目录> --analysis <已完成分析目录> --output <本仓库diagnostics下新目录> --handoff-package <已同步的SHA包.json>`。先同步Helper记录；分析目录必须有完整analysis-receipt.json，包/采集身份、预测清单及predictions.jsonl的SHA一致。未完成或被改写的分析拒绝导出成功清单。

## 逐局录音包入口

新逐局包使用同一命令，将 `--handoff-package` 替换为 `--audio-match-package <closed-matches/scope_…目录>`，可加 `--expected-package-id <清单SHA>`。`--run` 必须指向该包所属的原capture目录，`--analysis` 必须是对应逐局包已完成的冻结分析；未提供包SHA时也会固定分析收据中的SHA，不接受另一份包。两种来源参数不能同时使用。

导出只读取冻结候选和原PCM，不解码参考GSI。逐局包采用延后参考校验模式，仍在进入/退出时核对参考流原字节完整性；`reference_semantics_verified=false`不能当作语义核查通过。无需等整个capture停止或全局summary关闭，但本包必须完整封存。原WAV来源记录包含包ID、capture运行ID、文件名和SHA。

生成资料的实际CLI验证：`diagnostics/audio-match-listening-interop/20261026T211258458108Z/verification.json`。1段裁片共28,800采样帧，与跨两个原WAV的对应PCM逐样本一致，来源和冻结预测未改；页面保持未审核，全未审核提交不能生成听审结果。这是生成信号契约验证，不是真实听审或音效准确率。

## 抽样和截取

- 默认每技能最多3段、总数最多24段。按技能轮流分配名额，各技能优先取首尾，再取中间位置；只使用已冻结候选的技能、take、时间，不用GSI或调阈值。完全相同窗口去重，预算遗漏的技能明确列出。
- 每个候选原窗口前后各加0.6秒；开头裁到0，不造静音填充。输出16000Hz单声道int16 WAV，记录原WAV SHA及逐段采样帧范围。
- 跨文件只拼同一take、偏移无缺口且前段正常连续结束的PCM。暂停flush、丢失覆盖或不足尾部窗口均列unavailable，不把暂停两侧接成连续技能。
- 复验原闭合包及所有WAV，出口再次核对原分析回执、预测清单和预测SHA，最后原子发布review.json。中途失败可留下排查用裁片，但没有成功清单。
- 复听页用单独candidate_context_visible政策，明确没有录像/GSI施法真值，展示候选不是盲听。旧录像/GSI上下文页面和原26段资料不重写。
- 判断文件绑定本页清单与每段SHA；导出、恢复及导入继续校验。全部未听审的提交仍不能生成听审回执，判断不自动回写预测/参考库或进入训练。
